# Разделы технического задания по проекту Cognitive Kids

## 2. Общее описание системы

### 2.1 Контекст системы

Cognitive Kids представляет собой обучающую систему для детей дошкольного возраста, ориентированную на развитие памяти, внимания, логики, счета, классификации, прогнозирования и пространственного мышления. Система состоит из клиентского приложения, серверной части, локальной базы данных и web-версии, развернутой через GitHub Pages.

Проект рассчитан на несколько типов пользователей:

- администратор, который управляет пользователями и смотрит общую статистику платформы;
- родитель, который создает детские аккаунты, просматривает прогресс ребенка и управляет привязанными детьми;
- ребенок, который проходит игровые задания, получает результаты, взаимодействует с друзьями и участвует в рейтинге.

Основная пользовательская логика находится в мобильной/web-части проекта `mobile/src`. Серверная часть находится в `backend` и предоставляет REST API для авторизации, управления пользователями, результатов игр, статистики и друзей. Для демонстрации на GitHub Pages также реализован моковый API в `mobile/src/config/mockApi.js`, так как GitHub Pages является статическим хостингом и не запускает backend.

Система работает в двух режимах:

- полноценный режим с backend API на Express и SQLite;
- демонстрационный web-режим на GitHub Pages с моковыми данными `admin/admin` и `child/child`.

В полноценном режиме клиент отправляет HTTP-запросы через Axios на backend. Backend проверяет JWT-токен, права пользователя, обращается к SQLite через Sequelize и возвращает JSON-ответы. В демонстрационном режиме запросы перехватываются на клиенте и обслуживаются локальными моковыми ответами, чтобы приложение можно было показать без отдельного сервера.

### 2.2 Архитектурный подход

Архитектура проекта построена по клиент-серверному принципу с разделением ответственности между интерфейсом, бизнес-логикой клиента, API-слоем, серверными контроллерами и моделью данных.

Клиентская часть реализована на React Native и Expo. Это позволяет использовать одну кодовую базу для мобильной и web-версии. Для web-сборки применяется `react-native-web`, а публикация выполняется через GitHub Actions и GitHub Pages. Навигация построена на React Navigation: главный навигатор выбирает ветку приложения по роли пользователя, а внутри каждой роли используется свой набор вкладок и экранов.

Главная точка выбора пользовательского сценария находится в `mobile/src/navigation/AppNavigator.js`. Если пользователь не авторизован, открывается экран входа. После входа система смотрит на `user.role` и переключает приложение в один из трех контуров: `AdminNavigator`, `ParentNavigator` или `ChildNavigator`.

Клиентская авторизация реализована через `AuthContext` в `mobile/src/context/AuthContext.js`. Этот контекст хранит текущего пользователя, состояние загрузки, функции входа, выхода и обновления пользователя. Для сохранения токена и пользовательских данных используется `AsyncStorage`, что позволяет сохранять сессию между перезапусками приложения.

API-слой клиента находится в `mobile/src/config/api.js`. Для HTTP-запросов используется Axios. В запросы автоматически подставляется JWT-токен из `AsyncStorage`. При ошибке авторизации токен и пользовательские данные удаляются. В web-демо режиме подключается моковая логика из `mobile/src/config/mockApi.js`, которая имитирует ответы backend без реального сервера.

Серверная часть реализована на Node.js и Express. Основной файл запуска backend находится в `backend/server.js`. Сервер подключает middleware `cors`, `express.json`, `express.urlencoded`, регистрирует маршруты `/api/auth`, `/api/games`, `/api/friends`, `/api/admin` и запускается после подключения к базе данных.

Для хранения данных используется SQLite, подключенная через Sequelize. Конфигурация базы данных находится в `backend/config/db.js`. Такой выбор подходит для учебного проекта и локального прототипа: база хранится в одном файле, не требует отдельного серверного СУБД и легко переносится.

Модель данных описана в `backend/models`:

- `User.js` хранит пользователей с ролями `admin`, `parent`, `child`, данные ребенка, возраст, активность и связь ребенка с родителем;
- `GameResult.js` хранит результаты игр, баллы, уровень, время, попытки, статус завершения и дополнительные детали;
- `FriendRequest.js` хранит заявки в друзья между детскими аккаунтами;
- `index.js` собирает модели и определяет связи между ними.

Серверные маршруты разделены по функциональным областям:

- `backend/routes/auth.js` отвечает за вход, получение текущего пользователя, регистрацию родителей, регистрацию детей и удаление детей;
- `backend/routes/admin.js` отвечает за административное управление пользователями и общую статистику;
- `backend/routes/games.js` отвечает за сохранение результатов, статистику ребенка и рейтинг;
- `backend/routes/friends.js` отвечает за заявки в друзья, принятие, отклонение и список друзей.

Контроллеры находятся в `backend/controllers`. В них сосредоточена прикладная логика обработки запросов: проверка входных данных, обращение к моделям Sequelize, формирование JSON-ответов и обработка ошибок.

Безопасность backend построена на JWT и ролевой авторизации. Middleware в `backend/middleware/auth.js` извлекает токен из заголовка `Authorization`, проверяет его через `jsonwebtoken`, загружает пользователя из базы и ограничивает доступ по ролям через `authorize`. Для операций с данными ребенка используется дополнительная проверка доступа, чтобы родитель мог видеть только своих детей.

### 2.3 Основные функциональные блоки

#### 2.3.1 Авторизация и управление сессией

Функциональность авторизации состоит из экрана входа, клиентского контекста пользователя, хранения токена и серверного endpoint для проверки учетных данных.

Используемые технологии:

- React Native для формы входа и отображения ошибок;
- React Context API для хранения пользователя на уровне приложения;
- AsyncStorage для сохранения токена и данных пользователя;
- Axios для отправки запроса авторизации;
- Express для endpoint `/api/auth/login`;
- bcryptjs для проверки пароля;
- jsonwebtoken для генерации JWT;
- Sequelize для поиска пользователя в SQLite.

Ключевые файлы:

- `mobile/src/screens/LoginScreen.js`;
- `mobile/src/context/AuthContext.js`;
- `mobile/src/config/api.js`;
- `mobile/src/config/mockApi.js`;
- `backend/controllers/authController.js`;
- `backend/routes/auth.js`;
- `backend/models/User.js`.

Суть реализации: пользователь вводит логин и пароль, клиент вызывает `login` из `AuthContext`, затем отправляет POST-запрос на `/auth/login`. Backend ищет пользователя, сверяет пароль через `comparePassword`, проверяет активность аккаунта, создает JWT и возвращает объект пользователя. На клиенте токен и пользователь сохраняются в `AsyncStorage`, после чего `AppNavigator` переводит пользователя в нужный раздел по роли.

#### 2.3.2 Ролевая навигация

Функциональность ролевой навигации разделяет приложение на независимые пользовательские контуры.

Используемые технологии:

- React Navigation `NavigationContainer`;
- `createNativeStackNavigator` для стековой навигации;
- `createBottomTabNavigator` для нижних вкладок;
- React Context для получения текущего пользователя;
- локальный компонент `AppIcon` для web-совместимых иконок без зависимости от шрифтов.

Ключевые файлы:

- `mobile/src/navigation/AppNavigator.js`;
- `mobile/src/navigation/AdminNavigator.js`;
- `mobile/src/navigation/ParentNavigator.js`;
- `mobile/src/navigation/ChildNavigator.js`;
- `mobile/src/components/AppIcon.js`.

Суть реализации: `AppNavigator` проверяет наличие пользователя и его роль. Для администратора открываются вкладки панели управления, пользователей, статистики и профиля. Для родителя открываются главная, список детей, статистика и профиль. Для ребенка открываются игры, друзья, рейтинг и профиль, а игровые экраны подключены через stack-навигацию.

#### 2.3.3 Административный модуль

Административный модуль предназначен для управления пользователями и просмотра общей статистики системы.

Используемые технологии:

- React Native для экранов, списков, карточек и модальных окон;
- FlatList/ScrollView для вывода пользователей и статистики;
- Axios для запросов к backend;
- Express routes `/api/admin`;
- middleware `protect` и `authorize('admin')` для ограничения доступа;
- Sequelize для выборок пользователей и агрегированной статистики;
- SQLite для хранения пользователей и результатов игр.

Ключевые файлы:

- `mobile/src/screens/admin/AdminDashboardScreen.js`;
- `mobile/src/screens/admin/AdminUsersScreen.js`;
- `mobile/src/screens/admin/AdminStatisticsScreen.js`;
- `mobile/src/screens/admin/AdminProfileScreen.js`;
- `backend/routes/admin.js`;
- `backend/controllers/adminController.js`;
- `backend/models/User.js`;
- `backend/models/GameResult.js`.

Суть реализации: администратор видит количество пользователей, родителей, детей, активных аккаунтов, число сыгранных игр, активность за неделю и популярные игры. Через экран пользователей администратор может просматривать структуру родитель-дети, создавать родителей, активировать/деактивировать пользователей и удалять аккаунты. Backend дополнительно проверяет роль `admin`, чтобы эти действия не были доступны родителям или детям.

#### 2.3.4 Родительский модуль

Родительский модуль предназначен для управления детьми и анализа их прогресса.

Используемые технологии:

- React Native для форм, карточек, списков и модальных окон;
- `@react-native-community/datetimepicker` для выбора даты/возраста ребенка;
- React Context для доступа к текущему родителю и списку детей;
- Axios для регистрации и удаления детей;
- Express endpoint `/api/auth/register-child` и `/api/auth/child/:childId`;
- Express endpoint `/api/games/statistics/:childId`;
- Sequelize-связь `parent -> children`;
- SQLite для хранения детских аккаунтов и результатов.

Ключевые файлы:

- `mobile/src/screens/parent/ParentDashboardScreen.js`;
- `mobile/src/screens/parent/ParentChildrenScreen.js`;
- `mobile/src/screens/parent/ParentStatisticsScreen.js`;
- `mobile/src/screens/parent/ParentProfileScreen.js`;
- `backend/controllers/authController.js`;
- `backend/controllers/gameController.js`;
- `backend/middleware/auth.js`;
- `backend/models/User.js`;
- `backend/models/GameResult.js`.

Суть реализации: родитель может создавать аккаунты детей, указывать имя, логин, пароль и возраст. Возраст ограничен диапазоном 2-6 лет, что соответствует целевой аудитории приложения. Родитель может удалить только своего ребенка: backend проверяет `parentId`. В статистике родитель выбирает ребенка и получает количество игр, средний результат, прогресс по типам игр и рекомендации.

#### 2.3.5 Детский игровой модуль

Детский модуль содержит каталог развивающих игр и отдельные игровые экраны.

Используемые технологии:

- React Native компоненты `View`, `Text`, `TouchableOpacity`, `Modal`, `ScrollView`;
- React hooks `useState`, `useEffect`, `useContext`, `useRef`, `useCallback`;
- Animated и PanResponder для drag-and-drop в игре сортировки;
- Dimensions и responsive utilities для адаптации размера элементов;
- Axios для сохранения результата игры;
- Express endpoint `/api/games/result`;
- Sequelize model `GameResult` для хранения результатов;
- mock API для сохранения результатов в демонстрационном web-режиме.

Ключевые файлы:

- `mobile/src/screens/child/ChildDashboardScreen.js`;
- `mobile/src/screens/games/MemoryGameScreen.js`;
- `mobile/src/screens/games/OddOneOutGameScreen.js`;
- `mobile/src/screens/games/SortingGameScreen.js`;
- `mobile/src/screens/games/CountingGameScreen.js`;
- `mobile/src/screens/games/ShadowMatchingGameScreen.js`;
- `mobile/src/screens/games/BuildingGameScreen.js`;
- `mobile/src/screens/games/PredictingGameScreen.js`;
- `mobile/src/screens/games/ARAdventureGameScreen.js`;
- `backend/controllers/gameController.js`;
- `backend/routes/games.js`;
- `backend/models/GameResult.js`.

Состав игр:

- `Мемори` развивает память: ребенок открывает карточки и ищет пары. Размер сетки зависит от возраста ребенка. Используются эмодзи-символы, подсчет ходов, найденных пар, времени и эффективности.
- `Найди лишнее` развивает классификацию и внимание: ребенок выбирает объект, который не относится к группе. Есть подсказки, учет попыток и модальные окна обратной связи.
- `Сортировка` развивает категоризацию: ребенок распределяет предметы по корзинам. Для перемещения используется `Animated.ValueXY` и `PanResponder`, что дает интерактивный drag-and-drop сценарий.
- `Счет` развивает базовые математические навыки: ребенок считает предметы и выбирает правильный ответ.
- `Тени` развивает визуальное сопоставление: ребенок выбирает правильную тень для объекта.
- `Конструктор` развивает память и пространственное мышление: ребенок смотрит образец, затем собирает конструкцию из блоков.
- `Что дальше?` развивает причинно-следственное мышление: ребенок выбирает продолжение ситуации.
- `AR Приключение` подключает отдельное web/AR-приложение через WebView и обмен сообщениями.

После завершения игры клиент отправляет результат на `/games/result`. В результате сохраняются `gameType`, `level`, `score`, `maxScore`, `timeSpent`, `attempts`, `completed` и дополнительные `details`. Эти данные затем используются для статистики родителя, рейтинга и административной аналитики.

#### 2.3.6 Модуль друзей и рейтинга

Модуль друзей нужен для социального взаимодействия между детскими аккаунтами, а рейтинг показывает результаты ребенка и его друзей.

Используемые технологии:

- React Native FlatList, Modal, TouchableOpacity для списка друзей и заявок;
- Promise.all для параллельной загрузки друзей и заявок;
- Axios для запросов к `/friends` и `/games/leaderboard`;
- Express routes `/api/friends`;
- Sequelize many-to-many связь пользователей через таблицу дружбы;
- модель `FriendRequest` для заявок;
- SQL-запросы Sequelize для добавления и удаления дружеских связей.

Ключевые файлы:

- `mobile/src/screens/child/ChildFriendsScreen.js`;
- `mobile/src/screens/child/ChildLeaderboardScreen.js`;
- `backend/routes/friends.js`;
- `backend/controllers/friendController.js`;
- `backend/controllers/gameController.js`;
- `backend/models/FriendRequest.js`;
- `backend/models/User.js`.

Суть реализации: ребенок может отправить заявку другому ребенку по username, принять или отклонить входящую заявку, просматривать список друзей. Рейтинг строится на основе результатов текущего ребенка и его друзей. Backend ограничивает доступ к этим функциям ролью `child`.

#### 2.3.7 AR/web-игры

AR-модуль отделен от основного React Native приложения и находится в `mobile/ar-games`. Основное приложение открывает его через `ARAdventureGameScreen`.

Используемые технологии:

- React Native WebView для мобильного режима;
- отдельное web-приложение на Vite в `mobile/ar-games`;
- обмен сообщениями через `window.ReactNativeWebView.postMessage()`;
- GitHub Actions для сборки AR-части;
- GitHub Pages для публикации web-версии.

Ключевые файлы:

- `mobile/src/screens/games/ARAdventureGameScreen.js`;
- `mobile/ar-games/package.json`;
- `mobile/ar-games/vite.config.js`;
- `.github/workflows/deploy.yml`.

Суть реализации: AR-игра изолирована от основной навигации, но может передавать результат обратно в React Native экран. После получения сообщения экран сохраняет результат через API так же, как обычные игры.

Для web-версии также исправлены пути ассетов GitHub Pages и исключена зависимость от шрифтов иконок.

## 3. Функциональные требования

### 3.1 Авторизация пользователей

Система должна предоставлять вход по логину и паролю для пользователей с ролями `admin`, `parent`, `child`.

Реализация в коде:

- экран входа: `mobile/src/screens/LoginScreen.js`;
- хранение сессии: `mobile/src/context/AuthContext.js`;
- API-клиент: `mobile/src/config/api.js`;
- backend endpoint: `POST /api/auth/login` в `backend/controllers/authController.js`.

Технологии: React Native, React Context, AsyncStorage, Axios, Express, JWT, bcryptjs, Sequelize, SQLite.

### 3.2 Разделение доступа по ролям

Система должна автоматически открывать разные разделы приложения в зависимости от роли пользователя.

Реализация в коде:

- `mobile/src/navigation/AppNavigator.js` выбирает навигационный контур;
- `backend/middleware/auth.js` проверяет токен и роль пользователя;
- `authorize('admin')`, `authorize('parent')`, `authorize('child')` ограничивают backend endpoints.

Технологии: React Navigation, JWT middleware, Express middleware.

### 3.3 Функции администратора

Система должна позволять администратору:

- просматривать общую статистику платформы;
- видеть количество пользователей, родителей, детей и игр;
- просматривать популярные игры;
- создавать родительские аккаунты;
- активировать и деактивировать пользователей;
- удалять пользователей;
- просматривать связку родитель-дети.

Реализация в коде:

- `AdminDashboardScreen.js` отображает сводную статистику;
- `AdminUsersScreen.js` управляет пользователями;
- `AdminStatisticsScreen.js` показывает аналитику;

### 3.4 Функции родителя

Система должна позволять родителю:

- создавать детский аккаунт;

Технологии: React Native, DateTimePicker, Modal, Axios, Express, Sequelize associations, SQLite.

### 3.5 Функции ребенка

Система должна позволять ребенку:

- выбирать игру из каталога;

## 4. Нефункциональные требования

### 4.1 Производительность

Система должна обеспечивать плавную работу пользовательского интерфейса на мобильных устройствах и в браузере. Игровые экраны должны реагировать на действия пользователя без заметных задержек, так как целевая аудитория приложения - дети дошкольного возраста.

Реализация в проекте:

- игровые состояния хранятся локально через `useState`, поэтому действия в игре не требуют постоянных запросов к серверу;
- результат отправляется на backend только после завершения игры, что уменьшает сетевую нагрузку;
- списки пользователей, друзей и детей выводятся через FlatList, подходящий для списочных интерфейсов;
- адаптивные размеры вычисляются через `responsive.js`, что снижает риск тяжелых перерасчетов layout;
- web-сборка формируется статическими файлами, которые GitHub Pages отдает без серверной генерации.

Технологии: React hooks, React Native rendering, FlatList, static web export, GitHub Pages CDN/static hosting.

### 4.1.2 Время отклика

Требования к времени отклика:

- переходы между основными экранами должны выполняться визуально сразу после действия пользователя;
- игровые действия, такие как нажатие карточки, выбор ответа или перенос элемента, должны обрабатываться локально без обращения к серверу;
- запросы авторизации, статистики, друзей и результатов должны возвращать ответ в приемлемое для мобильного приложения время;
- в демонстрационном режиме mock API должен отвечать практически мгновенно, так как данные находятся на клиенте.

Реализация в проекте:

- `MemoryGameScreen` обрабатывает переворот карточек локально, а задержки `setTimeout` используются намеренно для UX, чтобы ребенок успел увидеть результат;
- `SortingGameScreen` использует `Animated` и `PanResponder`, чтобы drag-and-drop не зависел от сети;
- `ChildFriendsScreen` загружает друзей и заявки через `Promise.all`, сокращая общее время ожидания;
- `api.js` централизует HTTP-запросы и обработку ошибок;
- mock API в `mockApi.js` позволяет GitHub Pages версии работать без задержек backend.

### 4.2 Доступность и надежность

Система должна быть доступна пользователям через web-ссылку и в локальном мобильном режиме разработки. Приложение должно корректно обрабатывать ошибки авторизации, сетевые ошибки и отсутствие данных.

Реализация в проекте:

- GitHub Pages обеспечивает бесплатную доступность web-версии по публичной ссылке;
- GitHub Actions автоматически пересобирает приложение при пуше в `main`;
- workflow создает `404.html` для SPA routing, чтобы маршруты не ломались при обновлении страницы;
- backend возвращает JSON-ошибки и не раскрывает внутренние ошибки в production;
- `AuthContext` при невозможности обновить пользователя оставляет кэшированные данные;
- `api.js` удаляет токен при ошибке авторизации, чтобы пользователь не оставался в битой сессии;
- интерфейс использует loading-состояния, пустые состояния и модальные окна ошибок;
- демо-режим на GitHub Pages снижает зависимость от backend для презентации проекта.

Технологии: GitHub Pages, GitHub Actions, AsyncStorage, Express error middleware, loading states, modal feedback.

### 4.3 Требования к интерфейсу пользователя

Интерфейс должен быть понятным для детей, родителей и администратора. Детский контур должен быть визуально ярким, крупным и простым, а административный и родительский контуры должны предоставлять структурированную информацию.

Реализация в проекте:

- цветовые схемы различаются по ролям: админ использует фиолетовый акцент, родитель - зеленый, ребенок - оранжевый;
- нижние вкладки упрощают навигацию внутри каждой роли;
- игровые карточки используют крупные области нажатия, эмодзи, цветные блоки и простые подписи;
- модальные окна используются для результата игры, ошибок, подтверждения удаления, подсказок и выхода;
- `responsive.js` адаптирует размеры шрифтов, контейнеров и элементов под web/мобильные экраны;
- `AppIcon.js` заменяет font-icons на стабильные символы, чтобы web-версия не показывала квадраты при проблемах со шрифтами;
- в `LoginScreen.js` используется `expo-linear-gradient`, чтобы экран входа выглядел более дружелюбно.

Технологии: React Native StyleSheet, Modal, TouchableOpacity, ScrollView, FlatList, LinearGradient, responsive utilities, AppIcon.

### 4.4 Совместимость

Система должна работать в нескольких средах: мобильная разработка через Expo, web-сборка через Expo/React Native Web, статический хостинг GitHub Pages и backend Node.js.

Реализация в проекте:

- React Native позволяет использовать общие компоненты для мобильной и web-версии;
- Expo упрощает запуск приложения на Android, iOS и web;
- `react-native-web` обеспечивает запуск React Native компонентов в браузере;
- `network.js` выбирает API URL в зависимости от платформы и протокола;
- `app.json` задает web bundler `metro`;
- GitHub Actions использует Node.js 18, совместимый с используемыми зависимостями;
- backend использует SQLite, поэтому не требует отдельного PostgreSQL/MySQL сервера для локального запуска.

### 4.4.1 Программная совместимость

Клиентская часть совместима со следующими программными платформами:

- Expo SDK 50;
- React 18;
- React Native 0.73;
- React Native Web;
- современные браузеры для GitHub Pages версии;
- Android/iOS через Expo dev-среду.

Backend совместим со следующими программными платформами:

- Node.js;
- Express 4;
- Sequelize 6;
- SQLite;
- npm package ecosystem.

Инфраструктура совместима со следующими сервисами:

- GitHub repository;
- GitHub Actions;
- GitHub Pages;
- SSH remote push в GitHub.

### 4.4.2 Аппаратная совместимость

Система рассчитана на следующие типы устройств:

- смартфоны, на которых ребенок может проходить игры через крупные сенсорные элементы;
- планшеты, где интерфейс масштабируется за счет responsive utilities;
- ноутбуки и настольные компьютеры через web-версию GitHub Pages;
- устройство разработчика для локального запуска backend и Expo.

Особенности аппаратной совместимости:

- для обычных игр не требуется специализированное оборудование;
- для drag-and-drop сценариев поддерживаются сенсорные и мышиные взаимодействия через React Native/PanResponder;
- для AR/web-игр может потребоваться браузер или устройство с поддержкой камеры/AR-возможностей, в зависимости от конкретного сценария AR-части;
- SQLite backend может запускаться локально на обычном компьютере без отдельного сервера баз данных.
